# Licensing scope

SAMLscope contributors license their original software implementation, tools and
test code under Apache-2.0 ([LICENSE](LICENSE)). This grant does not cover incorporated
third-party text, schemas, code, images, fonts or dependencies.

SAMLscope-owned original contributions to requirement catalogs, test definitions,
profile mappings and explanatory prose are licensed under CC BY-SA 4.0
([CC BY-SA 4.0 text](LICENSES/CC-BY-SA-4.0.txt)). Attribute those contributions to **SAMLscope
contributors**, link https://github.com/sgrastar/SAMLscope, retain the license,
and identify your changes. This grant covers only rights held by SAMLscope
contributors. It does not assert that every field of a mixed document is original
or that third-party material can be relicensed under these terms.

Specification quotations, translations and adaptations retain the original
source's applicable terms and required attribution. In particular, Internet2
and the respective contributors remain credited for the Kantara Implementation
Profile under its CC BY-SA 3.0 US notice. OASIS document permissions are not
Creative Commons licenses. Historical document-specific terms are not replaced
by current publisher policies. The publication audit distinguishes references from incorporated expression;
see the [material review](LICENSES/material-review.md) and [publication audit](LICENSES/publication-audit.md).
Kantara-derived adaptations use CC BY-SA 4.0 as allowed by section 4(b) of
CC BY-SA 3.0 US, while original quoted material retains its original license.
Internet2 and all named contributors, the source title, URL and modification
credit are retained in the source registry.

Measured values, verdicts, identifiers and target declarations are not assigned a
Creative Commons license merely because they appear in an export. Public result
metadata contains static source notices only and adds no private Run inputs.

## Material and distribution boundaries

| Material | Applicable scope |
| --- | --- |
| Original Java, TypeScript, build tooling and original test implementations | Apache-2.0; incorporated third-party material is excluded |
| Original narrative, catalog/test-design explanations and mappings | CC BY-SA 4.0 for SAMLscope-owned contributions only |
| Mixed specification-derived definitions and documents | Original contribution grant above plus retained source terms; no single whole-file license claim |
| Third-party libraries, schemas, examples, fonts and images | Their original terms; unresolved material is not relicensed |
| Result measurements, user declarations and protocol captures | No content-license grant inferred from generation |

[The source-notice registry](LICENSES/source-notices.json) retains publisher notices and review status.
[The material index](LICENSES/material-index.json) is generated by [materials.py](dev/licensing/materials.py) from
signed catalogs and identifies source references per obligation, including test
instructions and linked variants. Attribution membership does not change
functional profiles, applicability, levels or verdicts.

New `result.json` files carry an `attribution` object with selected source notices,
the original-content license and explicit unresolved references. Existing saved
results are not rewritten. Standalone `report.html` displays the same metadata
and includes the software license; legacy results retain the bundled registry
fallback. The [application license page](https://app.samlscope.com/licenses) provides readable notices.

Application distributions retain these documents under `LICENSES`; application
JAR resources use `META-INF/samlscope`. Dependency JAR license/notice resources
must remain intact. Browser chunks retain included package notices, and the
browser notice download contains their full texts. The website generator embeds
only sources represented in its downloadable catalog.

[LICENSE](LICENSE) is the Apache license grant for original software. A separate Apache
`NOTICE` is not used as a replacement for third-party permissions: upstream
NOTICE files remain with their packages and specification notices remain in the
source registry. See [CONTRIBUTING.md](CONTRIBUTING.md) for contribution conditions.

## Find notices and publication conditions

The [license and source index](LICENSES/README.md) links the full terms, source
registries and distribution-specific evidence. For reuse or redistribution, consult
[the publication audit](LICENSES/publication-audit.md),
[the material-by-material register](LICENSES/publication-register.md), and
[the container notice and corresponding-source conditions](LICENSES/container-publication.md).
The register records the actual use, rights holders, permission evidence and
required notices for each reviewed material; the audit defines the scope of those decisions.
