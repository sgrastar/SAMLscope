# Keycloak ALG08 native policy acceptance and earlier diagnostic

The `IIP-ALG08-a-idp-01` and `IIP-ALG08-b-idp-01` observations for Keycloak are adopted as `PASS` in `browser_sso_idp` from Run `run_G0J99F02Y5VAVJPWY78CNTGBJP`. Evidence is in `build/acceptance/reference-20260930/keycloak-alg08-native-policy-v163-r4/`. A native Client Policy using `client-attributes` and `reject-request` prevents the selected key-transport algorithm. The campaign exercises both prevented sets, allowed encrypted responses, policy removal, and reversal of the prevented set. Native configuration rejection originals, read-back, protocol controls, and exact restoration are required together; merely selecting an algorithm cannot satisfy the case.

The adoption verifier `dev/reference-acceptance/verify_keycloak_algorithm_policy_acceptance.py` replays originals and invalid controls with the archived production Runner JAR. An independent `ecp_idp` campaign, Run `run_NZGX1PXRJSNF8EHNXYM2ADPGDP`, completed its SOAP controls and formal evaluation on `samlscope:reference-combined-v165`. Its originals are in `build/acceptance/reference-20260930/keycloak-alg08-native-policy-ecp-v164/`, and `dev/reference-acceptance/verify_keycloak_ecp_algorithm_policy_acceptance.py` independently verifies its native policy rejections, allowed signed/decryptable SOAP controls, restoration, and archived production replay. Both ECP cases are adopted as `PASS`; browser acceptance is not reused as ECP acceptance.

The earlier diagnostic evidence remains in `build/acceptance/reference-20260930/keycloak-alg08-capability-audit/`. No result from its provisional Run `run_SJA9ZG9NDBQ722QSNN5V3MN8B6` is selected by the comparison or remaining-audit generators.

The browser diagnostic created a temporary native client, selected RSA-1.5, then RSA-OAEP, then RSA-1.5 again, and observed the same key transport algorithms on three correlated successful responses. The client was deleted and its absence read back. The recorded Keycloak runtime, configuration, provider inventory, and main-JAR manifest were unchanged. This demonstrates algorithm selection; it does not establish that the product lacks a configurable prevention mechanism.

The earlier runtime scan covered all Keycloak JARs but searched a limited vocabulary, and its independent verifier checked only the live services JAR rather than independently rehashing and rescanning the full runtime. It did not establish capability absence. The subsequent native Client Policy campaign demonstrates a configurable prevention mechanism and supersedes that diagnostic for browser acceptance.

The earlier separate ECP attempt ended in `UNKNOWN_DELIVERY`: target metadata advertised a localhost SOAP endpoint that was unreachable from the Suite container. The temporary client was restored. This transport uncertainty is not a product failure and did not contribute to a verdict. The Suite-local forwarder was subsequently recreated against the current Suite container's network namespace, and the new ECP campaign completed its SOAP exchanges. The earlier diagnostic verifier rejects tampered runtime, scan, configuration read-back, wire-original, restoration, and failed-attempt records; it makes no conformance conclusion.
