# Reference-implementation audit of Keycloak NameID-omission capability

`IIP-IDP11-a-idp-01` is an approved CONFIG / MUST case requiring the IdP to generate an Assertion with no `NameID` in `Subject`. With `configuration_failure_semantics: normative_capability`, `capability_absent` becomes product FAIL only when absence of that configuration capability is established. Missing settings, insufficient privileges or incomplete evidence do not become FAIL.

<!--g1-literal--> Scope is limited to Keycloak 26.7.2 in fixed image `sha256:9d1f1b2b7261ff53c66cb1092dfcdc34a5fb77e81f9e6a6e75b8b6a795de8067`, `browser_sso_idp` Run `run_P57XA0ZDWHSVWX8PNW01MXSVT7`. Evidence: `build/acceptance/reference-20260930/keycloak-nameid-omission-probe-v2/`.

The administration UI offers SAML NameID Format values `username`, `email`, `transient` and `persistent`. The administration API saves arbitrary strings, but runtime `SamlClient.getNameIDFormat()` converts unknown values to `unspecified`. The installed NameID mapper is only the user attribute mapper; when it cannot return a value, `SamlProtocol.authenticated()` returns `STATUS_INVALID_NAMEIDPOLICY`. With a value, `SAML2Response.createResponseType()` places `NameIDType` in `Subject`. Later response mappers change only audience/AuthnContext. A still-later `SamlAuthenticationPreprocessor` SPI exists, but this image has no implementing provider. Client policy executor/custom provider paths were also audited.

<!--g1-literal--> All 471 runtime JAR live SHA-256 hashes match saved copies. The administration API lists 14 SAML mapper schemas. An independent verifier rescans every JAR and matches implementation classes, service registrations, relevant bytecode, UI assets, administration API and client-policy inventory. Capability absence is not inferred from UI-text search alone.

Created a temporary SAML client and executed SSO in the same Suite Run for normal behavior, unknown format `none`, a NameID mapper referencing an absent user attribute, and restored configuration. Normal, unknown-format and restored conditions each had `Subject/NameID` in original signed Success Assertions. The missing-value mapper produced a signed Responder with no Assertion. Independently verified request/response correlation, original-metadata signing keys, Response/Assertion signatures and original hashes. Explicitly deleted the mapper before reading back original client settings, then deleted the client and verified absence. No manual interactions occurred.

The first attempt, `keycloak-nameid-omission-probe-v1/`, showed that client `PUT` alone does not delete protocol mappers; its apparent restored response was therefore Responder. This failure is retained. v2 adds mapper-specific DELETE and exact configuration read-back. The v1 temporary client was also deleted; v1's restored response is not adopted as a control.

<!--g1-literal--> Independent `verify_keycloak_nameid_omission_absence.py` passed; all 7 temporary-copy mutation controls—JAR hash/count, custom provider, null-mapper response, baseline NameID, residual client and mapper inventory—were rejected for expected reasons. Afterwards the Suite CONFIG event generated `VIOLATED` / `FAIL` / `capability_absent` only for this case. The generator connects it to the comparison by rerunning the verifier. No inference extends to other products, ECP or future Keycloak versions.
