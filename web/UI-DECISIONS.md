# UI simplification decisions (Opus analysis, 2026-10-31)

Goal: OIDC-conformance-suite-style flow. Configure product -> one button -> auto-judge -> UI asks only for non-config actions (login/logout). Radically simple. Never show PASS/FAIL from UI; never hide NOT_VERIFIED; never persist credentials (AGENTS.md).

## RunManagement.tsx (current simplified draft exists; apply these)
P0-1. CONFIGURATION interactions with `completionMode === 'TRANSCRIPT_OR_OPERATOR'` must NOT be the primary card nor in the step list (their answers are only capability_absent / target_config_unavailable / capability_undetermined and `capability_absent` can become VIOLATED). They complete automatically from Transcript evidence. Put their answer forms only inside the metadata card's collapsed "If this can't be run on your product" per case, preface: "Normally judged automatically. Only choose if your product cannot do this." Use neutral labels: capability_absent = "My product does not support this (can affect the result)", target_config_unavailable = "Can't change this in my environment", capability_undetermined = "Don't know".
P0-2. Metadata fixture campaign must return in minimal form. Show only when `workspaceEvidence().protocolEvidence.eligibleCases > 0`; only then call `api.metadataLab(runId)`; never in read-only runs. Restore exported `metadataFixtureWork()` (copy from `git show HEAD:web/src/RunManagement.tsx`). Card "Metadata refresh tests (N)":
  1. `ingestionMode==='MANUAL_REFRESH'` && pendingVariants>0: one button "Start" -> `api.startAutomaticMetadataPolling(runId, pendingVariants, 15, csrf)`; then show returned `automaticStartUrl` as a link opening a new tab (do not window.open after await).
  2. `AUTOMATIC_POLLING` && !campaignComplete: progress "i / n" + link to `automaticStartUrl`; if `automaticContinueUrl`: `<form method="post" action=... target="_blank">` button "My product showed its result — continue" with note "Only advances the run; it is not a verdict."
  3. When campaign complete or `protocolEvidence.readyCases>0`: auto-call `api.evaluateProtocolEvidence` once per distinct state (no repeat loops). No "Re-evaluate" button.
  Collapsed "If your product doesn't re-fetch automatically": preloaded aggregate (`startPreloadedMetadataCampaign`; show preloadedMetadataUrl, preloadedDownloadUrl, preloadedStartUrl), `useManualMetadataRefresh`, "select next fixture" (`selectMetadataVariant(nextVariant)`), explicit button "I tried everything listed" -> `confirmProtocolEvidenceAttempts` (never automatic; note: "Cases without evidence stay not verified."), plus the P0-1 forms.
P0-3. Never hide NOT_VERIFIED. After round trip always show one line from `workspaceEvidence().campaigns`: "Verified automatically X · Self-attested Y · Not verified Z of N" + link "See why" -> `/reports/{runId}`. Z shown even when 0. Primary-card end states: if no pending interactions/probe and every classification resolved: "All tests finished". If unresolved remain but nothing to ask: "Z could not be verified automatically (they stay not verified and count in the total)" + results link. Do not use wording implying "all passed".
P0-4. Restore `resolvePrompt` (replace `<plan-id>`, `<run-id>` in `promptEn`) in InteractionCard and group cards.
P1-1. Shared operator actions: from `campaigns.campaigns` with `actionKind==='CONFIGURATION'`, `action.remainingCaseIds.length>1` and >=2 actual pending interactions: one card, one button "I made this setting change" -> `api.completeCampaignAction(runId, campaign.id, action.id, csrf)`; remove those cases from the individual list. Note: "This only records that you did it; without recorded traffic the cases stay not verified." Place inside ONE collapsed section "Tests that need a product setting change (N, optional)" after the main flow; OPERATOR-mode CONFIGURATION interactions (4-choice incl. confirmed) go in the same collapsed section, never the primary card.
P1-2. Wording: rename "Run tests again" -> "Continue tests" with hint "Press after you changed your product's settings" (startTests is resume, idempotent). "Done" -> "I did it" with note "The result comes from recorded traffic. No record = not verified." ECP outbox UNKNOWN_DELIVERY shown as "Delivery unknown (not counted as a product failure)".
P2. Do not restore grouped attestation. ATTESTATION interactions are never primary; put in last collapsed "Self-attestation (N, optional)" as individual cards. Delete: plan-progress cards, campaign overview, case workspace + drawer, export menu, read-only detail export. While `probeWaiting` or a TRANSCRIPT-completion interaction is pending: poll refresh every ~5s (or small Refresh link). If `focusCaseId` has no interaction: "No action needed for this case" + back link (not "Run tests").

## App.tsx
Flow: plan list -> "New test" -> one-screen form -> create -> go straight to Run page.
- self-hosted (initialRun null): after `createPlan` call `createRun`, navigate to `managementUrl` if present else `/manage/{runId}`; no automatic preflight (Run page "Check setup" does it).
- hosted w/o OIDC: keep one-time ManagementLink (secret) with a primary button; no auto navigation. OIDC: navigate directly.
- PlanDetail: drop `PeerRegistration` (it is in Run page "Connection details"), reachability text, RoundTripLink, Manage/Open branching. Keep only latest run status + Open, and "New run".
- PlanList: drop request-signing row and Refresh button; keep name, profile, latest status.
- Form keeps: profile (radio); saved target select (only if any) else Entity ID + metadata URL (required by registerTarget); authorization checkbox (required); for browser_sso_idp/metadata_idp only a checkbox "My IdP requires signed requests" (default off -> OPTIONAL).
- Drop and send defaults: `name` auto-generated (entityID hostname + profile; same value to registerTarget); `interaction: { allowBrowserSteps: true, allowAttestation: false, preset: 'assisted' }`; `suiteMetadataDelivery: 'HTTP_URL'`; `parameters: { clockSkewToleranceSeconds: 180, metadataRefreshWaitSeconds: 300, testUserHint: '' }`; `declaredFeatures: {}`.
